Frontend SPA

Vue 2 + Vuetify 2. Aplicación de página única con 40+ chunks de componentes cargados bajo demanda.

  • app.js — Núcleo: Vue, Vuex, Vue Router, Vuetify
  • Login.js — Autenticación (Firebase + JWT)
  • Home.js — Dashboard principal
  • Users.js, Clients.js, etc. — Módulos individuales
  • Carga lazy: Cada chunk se descarga solo cuando se navega a esa sección
⚙️

Backend API

Laravel 8 con 109 controladores REST que manejan toda la lógica de negocio y 101 modelos Eloquent.

  • Autenticación: tymon/jwt-auth con Firebase UID opcional
  • Middleware: jwt.auth protege rutas internas
  • Exportaciones: Laravel Excel + FPDF personalizado
  • Logs: Sistema de logging propio en app/classes/Logs.php
  • Notificaciones: Clase propia SendMail para correos
🗄️

Base de Datos

MySQL 8 con 119 tablas organizadas en catálogos (C_), transacciones (D_) y entidades (E_).

  • C_* — Catálogos base: artículos, modelos, productos, unidades, colores, empresas
  • D_* — Transacciones: órdenes, cotizaciones, compras, inventario, movimientos
  • E_* — Entidades: leads, órdenes, cotizaciones, secciones, garantías
  • Usuarios: c_erp_users + d_erp_access_users (permisos por módulo)
🔗

Integraciones

Conexión con Firebase Auth, API externa ASPEL (financiero) y Socket.io para tiempo real.

  • Firebase: Login con signInWithEmailAndPassword en producción
  • ASPEL: API externa para datos financieros (facturación, cartera vencida)
  • Socket.io: Tiempo real vía Laravel Echo + ws://localhost:3000
  • WebService: Clase app/classes/WebService.php para datos LB, RT, LS

🔐

JWT (JSON Web Token)

Los tokens JWT tienen validez de 24 horas (TTL = 1440 min). Se almacenan en Vuex y se envían en cada petición.

  • Claims: sub (user id), iat, exp, nbf, jti, prv (proveedor)
  • Algoritmo: HS256 (HMAC-SHA256)
  • Blacklist: Activada — tokens invalidados al cerrar sesión
  • Middleware: jwt.auth en todas las rutas protegidas
👥

Permisos por Módulo

Cada usuario tiene acceso granular a módulos y submódulos del sistema mediante d_erp_access_users.

  • Módulos: Dashboard, Usuarios, Clientes, Cotizaciones, Órdenes, Producción, etc.
  • Submódulos: Vistas específicas dentro de cada módulo
  • Roles: is_leader (líder), is_agent (agente)
  • Compañía: Cada usuario pertenece a una empresa (LS, RT, LB)

Ruta de navegacion completa

Desde el login hasta guardar un articulo, el camino que sigue el usuario en la interfaz.

  1. Login - Ingresa usuario/contraseña
  2. Home - Dashboard principal
  3. Menu lateral - Cotizaciones > Articulos
  4. Tabla - Visualiza todos los articulos activos
  5. Nuevo - Abre formulario en dialogo modal
  6. Guardar - Dispara peticion HTTP al backend
  7. Backend - Valida JWT, procesa, guarda en MySQL
  8. Respuesta - Actualiza tabla automaticamente

Codigo del controlador

El metodo store() en CArticleController.php que procesa la peticion.

public function store(Request $request)
{
    $article = new CArticle();
    $article->article = $request->article;
    $article->sku = $request->sku;
    $article->price = $request->price;
    $article->cost = $request->cost;
    $article->unit_id = $request->unit_id;
    $article->model_id = $request->model_id;
    $article->is_active = 1;
    $article->save();

    return response()->json([
        "success" => true,
        "message" => "Articulo creado",
        "data" => $article
    ], 200);
}
